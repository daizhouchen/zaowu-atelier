# 造物 · Atelier

> 创作者经营创作的工坊：AI 总管对内把内容质量做成**流水线机制**，对外把读者请进**创作流程**，底层把每一次创作沉淀为**可编排的资产**。

产品设计作品（PRD + 前后端完整 Demo）。产品要回答三个问题：

1. **优质内容怎么来** —— 不靠灵感，靠流水线：选题 → 起草 → 自检 → 内测 → 定稿 → 发布 → 复盘，每个阶段有状态、有规则、有产出物。
2. **读者怎么参与** —— 读者是共创者：报料人（素材+授权）、首读者（内测预读）、捉虫人（纠错补证），参与被署名、上墙、记入档案。
3. **经验怎么复利** —— 一切沉淀成资产：三个资产库 + 编排引擎，每次创作自动组装历史资产；捉虫确认即成为下一篇的自检规则。

## 三铁律（贯穿 PRD 与代码）

1. **无引用不调用**：引擎任何产出必须带资产引用锚点，Contract 校验失败直接丢弃（`engine.js → _contractProposal`）。
2. **AI 有提议权，没有决定权**：所有状态跃迁由创作者显式触发（`finalize/publish/retro` 均有前置校验）。
3. **一切留痕，一切沉淀**：被否决的提议、被驳回的自检意见同样写回资产库（编排日志全程可审计）。

## Demo 实现范围（PRD §10.1 MVP）

| 模块 | 已实现 |
|---|---|
| 流水线状态机 | idea → drafting → self_check → finalized → published → retro → archived，+ shelved 搁置（含理由写回选题库） |
| 选题触发器 | T1 新报料 × T2 需求信号聚类 × 搁置选题匹配；提议带 evidence_refs，Contract 校验失败即丢弃并记日志 |
| 资产装配 | 6 级优先级；风格档案必装；**未授权素材硬规则拦截**（装配清单与日志可见） |
| 起草 | 段落编辑、AI 段落色标 + 过目转正、拖入式引用（锚点自动登记 + 署名同步） |
| 自检 | C1 以偏概全 / C2 数据无来源 / C4 禁用表达 + **规则库注入**（捉虫衍生规则自动命中）；采纳/驳回（驳回写回负样本） |
| 定稿发布 | 前置校验（自检全处理 + 无未转正 AI 段）、创作方式声明自动生成、署名按实际引用锚点核验 |
| 复盘归档 | 资产清点 + 创作档案定型（不可变） |
| 读者共创 | 报料（结构化萃取 + 三档授权 + 可撤回）、捉虫（确认 → 修订痕迹 + 贡献者墙 + 自检规则）、需求信号投稿 |
| 小铺呈现 | 铺头数据、工坊橱窗、作品陈列、诞生档案（档案公开字段投影）、修订痕迹、贡献者墙 |
| 资产库 | 三库实时视图、素材卡萃取结果、自检规则库复利统计、资产利用矩阵、编排日志审计 |

自检为**确定性规则实现**（数字无引用、全称结论支撑不足、禁用表达、规则库关键词命中），每条意见带原文锚点与置信度——演示的是"质量机制"的产品结构，而非模型能力本身。

## 本地运行（全栈模式）

```bash
cd server
npm install
npm start        # → http://localhost:8787 （后端 + 前端一起托管）
```

前端探活 `/api/health`：连得上走 Express + data.json 持久化；连不上自动降级为浏览器内引擎（同一份 `shared/engine.js` + localStorage），所以 GitHub Pages 静态托管也能体验完整循环。页面右上角徽标显示当前模式。

## 推荐体验路径（5 分钟跑通复利飞轮）

1. 小铺 → 提交一条含「转行」的报料 → 引擎 T1/T2 命中，工作台案头出现选题提议
2. 工作台 → 确认提议 → 自动装配（注意资产抽屉里被拦截的未授权素材）
3. 起草 → 「让引擎起草背景段」插入带数据的 AI 段 → 引用素材 → 提交自检
4. 处理自检（试一次「驳回」，看负样本写回规则库）→ 定稿（试在 AI 段未转正时定稿，看硬规则拦截）→ 发布
5. 小铺 → 对已发布文章捉虫 → 工作台裁决确认 → 再建一篇含相同关键词的新稿提交自检，看衍生规则自动命中
6. 资产库 → 看编排日志与素材卡的一生
